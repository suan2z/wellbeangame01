## 3. 핵심 게임플레이

### 코어 루프 (현재 구현)

```
시작 → 좌우 이동(드래그) → 자동 사격 → 일반 적/무기상자/부대원 아이템 처리
   ↓
웨이브 보스 등장 → 처치 → 강화 카드 3중 1 선택
   ↓ (웨이브 반복: 스테이지당 4 + 스테이지 개)
스테이지 클리어 → 무기·화력 버프 + 부대원 초기화(점수 유지) → 다음 스테이지(무한)
   ↓
부대원 전멸 → 게임오버 → 하이스코어 저장 → 재시작
```

> 컨셉 단계의 "게이트 통과 / 골드 / 다음 챕터"는 아직 미구현이며 아래 해당 절에 별도 표기.

### 조작

| 입력 | 동작 |
|------|------|
| 화면 좌우 드래그 | 부대 좌우 이동 (3레인) |
| (자동) | 적을 향해 자동 사격 |
| 우하단 버튼(예정) | 액티브 스킬(폭탄, 회복 등) |

**한 손 엄지 조작** 만으로 모든 플레이가 가능해야 함 (지하철·버스 시나리오).

### 게이트 시스템 (핵심 차별화) ⚠️ 미구현 — 향후 도입 검토

> 현재 빌드에는 게이트가 없다. 대신 **무기 상자 / 부대원 아이템 / 보스 강화 카드**가 강화 선택지 역할을 한다. 아래는 향후 도입 검토용 설계.

부대가 전진하다 만나는 두 갈래 게이트. 어느 쪽으로 통과하느냐에 따라 효과 적용.

#### 게이트 종류

| 타입 | 예시 | 비고 |
|------|------|------|
| **인원 합산** | `+5명` vs `×2배` | 부대원 수 증가 |
| **무기 업그레이드** | `권총 → 기관총` vs `샷건` | 화력 변경 |
| **속성 강화** | `대미지 +20%` vs `사거리 +30%` | 스탯 부스트 |
| **함정** | `+10명` vs `÷2 + 골드` | 위험 감수 선택 |

> 한 판에 게이트는 평균 4~6개. **선택의 즉흥성**이 게임의 맛.

### 적/웨이브 구성

상세 명세는 별도 문서: [적 / 웨이브](적.md)

요약:
- 현재 구현: Normal 1종 (60ms 간격, **18px/s**)
- **스테이지/웨이브 구조**: 스테이지 1부터 무한, 스테이지당 웨이브 = `4 + 스테이지`
- 웨이브 = 보스 1마리. 보스 외형 5종 순환 + 탄막 5종(조준/3-way/5-way/점사/전방위) 순환
- 보스 HP는 `1 + (스테이지-1)×0.5 + (웨이브-1)×0.12` 배율로 가산
- 보스 처치 시 강화 선택 (데미지/연사/부대원/이동/점수/발사체)
- 향후: Runner / Tanker / 자폭 / 분열 / 실드 추가 예정

### 진행 / 실패 조건

- **클리어**: 보스 처치 + 부대원 1명 이상 생존
- **실패**: 부대원 전원 사망

## 4. 콘텐츠 구성

### 캐릭터 / 부대원

부대원은 화면 하단에 **해바라기(phyllotaxis) 원형**으로 밀집 배치됨. 모두 동일한 무기를 동시에 발사. 적과 충돌 시 1명씩 손실, 0명이 되면 게임오버. **장착 무기 등급에 따라 부대원 외형(전투기 디자인)이 변한다** — 상세는 [무기 문서](무기.md) 참조.

**표시 인원 vs 실제 전투원**: 표시 인원은 최대 **100명**까지 늘지만, 10명을 넘으면 보정이 들어가 화면에 그려지고 실제 사격하는 전투원 수는 완만하게만 증가한다. 표시 100명 = 실제 **30명**.

- 매핑: `실제 = 표시` (≤10명) → 10명 초과분은 `10 + (표시-10) × 20/90` 으로 보정 (반올림)
- 예: 표시 10 → 실제 10 · 표시 55 → 실제 20 · 표시 100 → 실제 30
- **부대원 증가 시** 부대 전체가 반짝이는 연출(틴트 플래시 + 스케일 팝 + 금빛 파티클)이 재생된다.

| 항목 | 값 |
|------|----|
| 시작 부대원 수 | 1명 |
| 표시 최대 인원 | 100명 |
| 실제 전투원 최대 | 30명 (표시 100명일 때) |
| 부대원 배치 | 해바라기(phyllotaxis) 원형 분포 |
| 손실 시 무적 시간 | 0.5초 |

**부대원 아이템**: 좌/우 영역에서 낙하, -1 / +1 / +2 / ?(랜덤) 4종

### 무기 (구현 완료)

상세 명세는 별도 문서: [무기](무기.md)

요약:
- **10종 (T1~T10)**: 권총 / 기관단총 / 샷건 / 라이플 / 듀얼권총 / 저격총 / 화염방사기 / 기관총 / 핸드캐논 / 가우스라이플
- DMG·간격·발사 수·확산이 모두 다름, DPS 오름차순 등급
- **스테이지별 드롭 등급 상한** (`maxTier = 2 + 스테이지`, 최대 10) — 초반엔 강한 무기 미드롭
- 중앙 3레인 낙하 무기 상자 파괴로 랜덤 획득 ([무기 상자 시스템](상자.md))
- **무기 등급별 부대원 외형 변화** — 강한 무기일수록 강력한 전투기 디자인 (날개/엔진/오라/무기색)
- 향후: 로켓 / 레이저 / 수류탄 추가 예정

### 필드 픽업 — 현재 구현

| 픽업 | 효과 |
|------|------|
| **무기 상자** | 파괴 시 랜덤 무기 드롭 (등급 상한 = `2 + 스테이지`) |
| **무기 드롭 아이템** | 부대원이 닿으면 즉시 무기 교체 |
| **부대원 아이템** | -1 / +1 / +2 / ?(랜덤) |

| 아이템 | 효과 |
|--------|------|
| 골드 코인 | 스테이지 후 영구 업그레이드 재화 |
| 보호막 | 일정 시간 무적 |
| 폭탄 | 화면 내 적 일소 |
| 자석 | 코인 자동 흡수 |

### 스테이지 구조

**현재 구현**: 스테이지 1부터 **무한 진행**. 스테이지당 웨이브 = `4 + 스테이지`(S1=5, S2=6, …). 스테이지 클리어 시 무기·화력 버프와 부대원을 초기화(부대원은 시작 1명으로 리셋)하고 점수는 누적. 배경 팔레트가 스테이지마다 순환(보라→청록→적색→블루→노을).

**향후(컨셉)** ⚠️ 미구현:

- **챕터제**: 1챕터당 10스테이지 + 챕터 보스
- **테마**: 시내 → 군사기지 → 지하터널 → 해변 → 우주정거장
- **출시 목표**: 챕터 5개 (총 50+ 스테이지)
- **무한 모드**: 영구 업그레이드용 골드 파밍 (현재 무한 진행이 그 원형)

### 메타 진행 (영구 업그레이드) ⚠️ 미구현 — 향후 도입

> 현재는 판마다 처음부터 시작하는 세션형. 판 간 영구 강화는 아직 없다. 아래는 향후 설계.

스테이지 클리어로 얻은 골드로 메인 메뉴에서 영구 강화:

- 시작 부대원 수 +N
- 기본 대미지 +%
- 사거리 +%
- 골드 획득량 +%
- 추가 슬롯/스킬 해금

> 메타 진행이 **"한 판 더!"**의 동력.

### 인게임 HUD (현재 구현)

- **상단 좌**: SCORE · **상단 우**: BEST(하이스코어) · **상단 중앙**: 부대원 수 / 무기 라벨(`[T등급] 이름`)
- **상단 중앙 아래**: 보스 상태(`스테이지 N · 웨이브 M/총 · HP`) / 스테이지 클리어 팝업
- **중앙**: 게임 화면 (좌우 부대원 아이템 구역 + 중앙 전투 구역)
- **하단 좌측**: 소리 ON/OFF 토글
- *(예정)* 일시정지 · 액티브 스킬 버튼

### 결과 화면 (게임오버)

**현재 구현**: `GAME OVER` + 최종 점수 + 최고 점수 + 신기록 표시 + **다시하기** 버튼(화면 터치로 재시작).

**향후** ⚠️ 미구현: 획득 골드 / 처치 수 통계, **광고 보고 보상 2배**, 다음 스테이지·메뉴 분기.

### 튜토리얼 ⚠️ 미구현

(향후) 첫 스테이지에 걸쳐 분할 학습:
1. 좌우 드래그로 이동
2. 무기 상자·아이템 활용
3. 보스전 + 강화 선택

| **로컬 저장** | `localStorage` (하이스코어) |
| **배포** | GitHub Actions → GitHub Pages (`/play`) + MkDocs 문서 |

### 향후 (네이티브/출시 단계, 예정)

| 영역 | 후보 |
|------|------|
| **네이티브 래핑** | Capacitor(웹 그대로) 또는 Unity 6 LTS 재구현 |
| **광고 SDK** | Google AdMob |
| **IAP** | (네이티브 선택에 따라) Unity IAP / 플랫폼 결제 |
| **분석** | Firebase Analytics 검토 |
| **아트** | 현재 절차적 도형 → 향후 카툰 에셋/외주 검토 |

### 오프라인 설계 원칙

- 모든 게임 로직 클라이언트 처리
- 결제만 IAP 영수증 검증 (Google Play 측)
- **세이브 데이터 보호**: PlayerPrefs는 평문이라 변조 가능 → JSON + 간단 해시 검증
- **시간 조작 방지**: 일일 보상은 디바이스 시간 변화 감지 (오프라인 한계 인정)
